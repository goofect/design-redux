Design Redux 2.1 build plan
Oct 18, 2026

· ​@Aidan

2.1 is six changes, each built in its own Claude Code session and released on its own: a
reading outline that follows you, a library that notices what you've read, a Study mode
with a revisit schedule, a way to present a map, an album and its map kept in step, and a
hardening pass. They build on what 2.0 already has — reading history, the library index,
the canvas map and the actions list — and write nothing new into your notes. Each section
below is a spec: what you get, where it lives in the code, the settings and commands it
adds, how it's tested, and when it's done.

Rules every task follows
These come from AGENTS.md and the code as it is now. Each Claude Code session reads
this section and its own change.
One change per session, released on its own. Smallest complete change; no rewriting
files or touching unrelated code.
Nothing new is written into your notes. Reading, revisit and presenting state lives in
the plugin's own data. The one exception is Change 5, which writes a note's parent
property only when you confirm it, through plugin.notes.write(file, change, {
undo }) , never processFrontMatter .
Every feature is a class extending Feature (or CanvasFeature ) with
settingsSchema() , actions() , register() , enable() / disable() and
X.settingKey . enable() must be safe to call repeatedly, and disable() must leave

nothing behind. What it does is written once in actions() .
New settings go in DEFAULTS (020) and in SETTINGS_TABS (360). Settings keyed by a
file path go in PATH_KEYED so they follow renames. A changed shape of saved data is a
numbered step in SETTINGS_MIGRATIONS , with the backup the loader already makes.
Never drop a command id or a setting key without a migration.
Layers. A piece uses its own area and those below. Canvas pieces reach Obsidian's
canvas only through core/079-canvas-adapter , behind typeof checks with a
fallback. tests/test_layers.js refuses a new crossing.
Obsidian rules that have bitten: no regex lookbehind; hover styles only inside @media
(any-hover: hover) ; menu entries need a section; settings code uses the tab's own

elements; no field called scope on a Modal .

Testing, lightly. Run the suites the change touches ( node tests/run.js canvas qol ),
all of them before pushing ( npm test ), and one real-Obsidian test only for what a
simulation can't show ( tests/e2e.sh "name" ). After pushing, tests/ci.sh once.
Done means: the acceptance list in the change's section holds, the lifecycle and layer
snapshots are updated on purpose, and CI is green on both Obsidian versions.

The six changes at a glance
Build them in this order: each one makes the next cheaper, and the first two are small
enough to land in a day each.

Change 1: a reading outline that follows you
What you get. A panel in the right sidebar listing the open note's headings, the way a
music app follows lyrics. The heading you're reading is lit, the ones above it are dimmed as
done, and each shows how many words are left in its section. Click a heading to jump to it.
Separately, every note reopens at the line you were on, and "Continue reading" opens
there.

Behaviour
Current heading. In reading view, the last heading whose top is above the middle of
the viewport. In editing view, the heading at the top visible line of the editor. Computed
from the cached heading list, so it needs no parsing of the note.
Panel rows. Indented by heading level; the current row accent-coloured with a thin
progress line under it, showing how far through that section you are; a small grey word
count on the right.
Jump. Click a row to scroll the note to that heading in whichever view is open. Arrow
keys move through the rows, and Enter jumps.
Follows without fighting. Scrolling the note moves the highlight. Scrolling the panel
doesn't move the note, and the panel stops auto-scrolling for 3 seconds after you scroll
it yourself.
Remembered place. The line you were on is saved when you leave a note (or every 5
seconds while you scroll). Reopening a note from a shelf, search, the queue or a link
restores it, unless the link names its own heading or line.
Study mode (workspace modes, 348) opens this panel on the right.

Change 2: a library that notices
What you get. The library shows what you've read without you asking: a ring on each
album's cover, a Home shelf of notes your reading points to, and a list of notes that are too
thin to be much use.

2a. Progress rings
Where. Bottom-right corner of an album's cover on tiles and in the album header, and in
the sidebar row as a small ring in place of the count when the album is in progress.
What it shows. Notes read out of notes in the album, from
Reading.countRead(files) . Nothing for 0 read; a ring for some; a check mark for all.
Subfolders count as part of the album.
How. A small SVG ring (a circle with stroke-dasharray ), sized by the density unit
from the appearance piece, coloured with the accent. Drawn by the same code that
draws covers, so albums, collections and shelves all get it.
Setting. albumProgressRing (default true), under Look.

2b. From what you read
A Home shelf of up to 12 notes: notes that notes you read in the last 14 days link to,
which you haven't opened yet, ranked by how many recently read notes point at them,
then by most recently linked.
How. Reading.latest('read', 40) gives the recent notes;
libraryIndex(plugin).outgoing(file) gives their links; Reading.state(file) says

whether a target was opened. The ranking is a pure function fromReading(recent,
outgoing, state, now) , tested on its own.
Shelf id fromReading , added beside continue , recents , added and collections in
Home's shelf list (110) and in the shelf choices in settings. Hidden when empty.
Setting. homeFromReading (default true), and the window fromReadingDays (14).

2c. Thin notes
A check in "Review the library" ( LibraryCheck , 259) listing notes under
thinNoteWords words (default 60), not counting properties, a heading, or embedded

content, newest first, each with its word count and a button to open it. Folder notes
and notes in the excluded folders from the existing setting are skipped.
Also a one-line count on Home's review card, and a dotted underline on the row's word
count in a list when the note is thin.
Setting. thinNoteWords (60; 0 turns it off).

Where it lives
A new library/ piece for the ring drawing and the two pure ranking and counting
functions; small edits in 110-browse-screens.js , the cover drawing in ui/ , and 259library-check.js . No new data is stored: everything is read from the reading log and

the index.

Tests
Simulation: ring fraction for 0, some and all read, with subfolders; fromReading ranking
and ties; thin-note detection with frontmatter, headings and embeds.
The existing 500-album timing test keeps running: the ring must add under 10 ms there.

Done when
1. A half-read album shows a half ring on its cover everywhere covers appear; an unread
or finished album doesn't show the ring.
2. The shelf is empty until you've read something that links elsewhere, and never lists a
note you've opened.
3. The thin-notes list matches a hand count on a test vault.
4. The 500-album shelf draws within 10% of today's time.

Change 3: Study
What you get. Notes you want to remember come back when you're about to forget them.
You choose which albums are studied; the plugin schedules revisits, runs a study session
through an album, and collects the passages you highlighted. Nothing is written into your
notes. It ships in three releases: 3a the schedule, 3b sessions, 3c highlights.

data.json is rewritten on every settings save.

A new core piece, StudyStore : loads once, saves debounced like Reading.save() ,
and follows renames and deletes (the same job Orders.followRename does for
settings keyed by path). Pure scheduling lives beside it as nextDue(item, grade,
ladder, now) so it can be tested without Obsidian.

Studied albums are a setting, studyAlbums (a list of folder paths), kept in PATH_KEYED
so renaming a folder keeps it studied.

3a. The revisit schedule
Turn it on per album: an album's menu has "Study this album". Its notes get items when
first read after that (so nothing is scheduled you haven't read), or all at once with "Add
every note".
The ladder. After a note is read, it's due again after the first interval of studyLadder
(default 1, 3, 7, 21, 60 days). Got it moves it up a rung. Again drops it to the first rung
(due tomorrow) and counts a lapse. Later pushes it one day. A note at the top rung is
due again at the top interval and stays.
Where you see it.
A To revisit shelf on Home with a count, hidden when nothing is due.
A chip in the strip, "3 to revisit", which opens the first due note.
On a due note's page, a quiet row under the title with the three grades.
In Study mode, Up Next is filled with the due notes in order of how overdue they are.
A daily cap, studyDailyMax (default 20), so a long backlog doesn't arrive at once.
Commands (actions, on: 'note' ): study-add-note , study-grade-got-it , studygrade-again , study-grade-later , study-open-next-due .

Settings (Study tab, new): studyEnabled (default false), studyLadder ,
studyDailyMax , studyAlbums .

3b. Study sessions
Start: "Study session" in an album's menu and in Study mode. The session queues the
album's notes, unread first, then those due, using the existing queue service, and
enters Study mode.
During: the strip shows "Session · 4 of 17". Reaching the end of a note counts it read
(Reading already does this). A "Mark to revisit" button on the strip adds the note to the
schedule.
End: a small summary dialog: "12 of 17 read · 3 marked to revisit · 41 min", with a button
to add the marked ones, and one to start another session on what's left. The session is
saved to sessions for the last-50 history, shown on the album's page as "Last studied
3 days ago".
Commands: study-start-session , study-end-session .

3c. Highlights and quizzes
Collected. Text between == marks in your notes is gathered per note, by scanning a
note's text when it's changed (cached by modified time in memory; no scan of the
whole vault at once, and none at all unless the Highlights screen or quiz is opened).
A Highlights screen, vault-wide or per album: each passage, its note, and a click that
opens the note at that line. Actions on hover: copy as a quote, add as a card to the open
canvas.
A quiz from highlights in studied albums: the passage with its highlighted words
hidden; reveal, then Got it or Again. Cards use the same ladder as notes and are keyed
by note path and a hash of the passage, so editing a passage starts it fresh and a
rename keeps it.
Settings: studyHighlights (default true once study is on), studyCardMax per day
(10).

Change 4: present a map
What you get. A mind map you can step through like a talk or a revision pass: the view
zooms to one card at a time, the rest of the map fades back, and a trail at the bottom says
where you are. It works on any canvas that has a tree of arrows, not only maps made with
the map engine.

Behaviour
The order. Depth first from the root card, children in sibling order ( orderedBranch and
siblingOrder in 325-canvas-layouts ). With a card selected, the presentation starts

from that card's branch. A folded branch is one step; stepping into it unfolds it for the
duration and folds it again after.
A step. The view animates to the card with padding, the card and its ancestors stay at
full strength, and everything else fades to 15%. A file card also shows the note's
opening lines in a caption under the card.
The trail. A bar at the bottom: Root › Branch › Card · 7 of 23 , each name clickable
to jump.
Keys. Right arrow or Space: next. Left arrow: back. Up and Down: parent and first child.
R : reveal mode, where cards not yet visited stay hidden until reached. O : zoom out to
the whole map and back. Escape: leave.
Leaving restores the viewport, the selection and any fold it opened, so a presentation
never changes the canvas. It saves nothing and writes no step of Undo.
Read-only while presenting: edits are blocked so a stray key can't change the map.
Entry points: a Present button in the map toolbar (349), the canvas menu, and
present-map in the command list. Study mode on a canvas offers it too.

Change 5: an album and its map kept in step
What you get. One command turns an album into a live mind map laid out by the parent
property you already use for graph routes, so a folder like Jurisprudence Concepts
becomes a map of how its notes hang from each other. The map stays current as notes

Untitled

change, and re-linking a card on the map can set that note's parent, so the map and the
notes never disagree.

Behaviour
Mapping an album. map-album (an album's menu and the command list) creates
<Album> map.canvas beside the folder note, or opens it if it exists. Each note is a file

card. The tree comes from parent (the property named in graphRouteProperty ),
read from the library index. Notes with no parent hang from the folder note, which is
the root. The canvas is added to canvasMapFiles , so the map engine lays it out, with
the layout chosen in the dialog (To the right by default).
Notes to map (automatic). While the canvas is open, a change to the album's notes
( metadataCache changed , debounced 500 ms) updates the map: a new note appears
as a card under its parent; a renamed or deleted note's card follows or is removed; a
changed parent re-links the arrow; the layout glides. Cards you moved by hand keep
their nudges.
Map to notes (asked). Dragging a card onto another to re-link it (a gesture the map
already has) asks "Set parent of 'X' to 'Y'?" with Set, Just on the map, and Always set.
The choice is the setting albumMapWritesParent ( ask | always | never , default
ask ). Writing goes through plugin.notes.write(file, { parent: '[[Y]]' }, {
undo }) , so the change shows in the note's properties and Undo restores them.

Removing a card removes the card only. Its note is kept, and the map records it as left
out ( leftOut in the canvas's canvasMapFiles entry) so it isn't added back. "Add a
left-out note" in the card menu brings one back.
Notes outside the album named as a parent appear as dimmed cards labelled with
their folder, and aren't mapped further.
Edge cases, all with a Notice naming the notes:
A cycle (A under B under A): broken at the first repeat; the later arrow is drawn as a
dashed cross-link.
Several parents in a list: the first is the tree edge; the rest become dashed crosslinks.
A parent that is plain text, a wikilink, a link with an alias or a path: all resolved the
way the graph routes resolve them (one shared function).
A parent naming no note: the note hangs from the root and the Notice says so.
